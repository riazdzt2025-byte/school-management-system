## ৪. বাকি ঝুঁকি / উল্লেখ্য

- **`admission_class` CharField** ⇒ class-স্তরের ক্রম এখনো textual (`'10' < '9'`); EX-02-এর scope ছিল **roll** order, তাই বদলানো হয়নি। আলাদা follow-up হিসেবে প্রস্তাবিত (numeric class sort), owner চাইলে পরের কোনো সেশনে।
- **Attendance class list-এর ক্রম বদল** (name → roll): ব্যবহারকারী-দৃশ্য পরিবর্তন; §৮-এর সুপারিশ অনুযায়ী roll নেওয়া হয়েছে। name-order ফেরত চাইলে এক লাইনের বদল।
- **Published Result-এর ক্রম বদল** (merit → roll): এই পেজে Position কলাম আছে, কিন্তু সারিটা পুরো ক্লাসের register (Fail/No-Marks-সহ), যাদের কোনো position নেই — তাই merit দিয়ে পুরো টেবিল সাজানো যায় না। ranking-এর জন্য `full_rank_list` / `top_10` merit-order-এই আছে। owner ভিন্ন মত দিলে `sort_result_rows_by_roll` সরালেই আগের আচরণ ফিরবে (টেস্টটি সেই সিদ্ধান্তের প্রহরী)।

## ৫. owner-সিদ্ধান্ত (§৮) — কীভাবে নেওয়া হলো

1. **`download_student_list` / `class_section_summary`-এ roll নাকি name** — সুপারিশ অনুসরণ: **roll** (`download_student_list` student list করে, তাই numeric roll order)। `class_section_summary` প্রযোজ্য নয় — সেখানে student সারি নেই, শুধু class/section-ভিত্তিক count (docstring-এ লেখা)।
2. **Roll `None` থাকলে সবার শেষে** — সুপারিশ অনুসরণ: **শেষে**; `nulls_last=True` দিয়ে sqlite/postgres-এ একই।
3. **Published Result-এর ক্রম** (§৮-এ ছিল না, সেশনেই সিদ্ধান্ত) — **roll order**; কারণ ও বিকল্প §৪-এ। ভিন্ন মত হলে জানালে ফেরত নেওয়া হবে।
4. **PR merge** — owner-এর অনুমোদনের অপেক্ষায়; এজেন্ট merge করবে না।
