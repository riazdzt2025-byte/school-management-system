# DB-03 - Permissions and data isolation (part 1: route guard matrix)

Date: 2026-09-21. Base: main at 67956c1.

## What was checked

All 108 named routes (216 requests, GET and POST) were requested over real HTTP
as an anonymous visitor.

| Result | Count |
|---|---|
| Refused (302 to login) | 207 |
| Public on purpose (200) | 6 requests / 3 routes |
| Not applicable (logout GET 405, media 404) | 3 |

Public routes, reviewed: `login`, `public_admission_apply` (rate limited),
`admission_dropdown_options` (JSON with group names and section letters only).

Pinned by `students/test_route_guards.py`: any new route that answers an
anonymous visitor with anything but a refusal fails the test. The test was
verified to fail when an unguarded route is added.

The login gate is pinned too: a non-admin user needs an active
`InstitutionAccess` row for the chosen institution and department.

## Findings that need an owner decision (no code changed)

1. **Read access across departments.** After a normal login, Office, Exam and
   Accounts clerks can all open the employee list, receipts, vouchers, salary
   sheets, the finance dashboard and the class/section summary (Accounts is
   refused only on the attendance pages). This matches the original rule
   "every department can view all modules", but salary and finance pages are
   sensitive. Decision: keep, or restrict those pages to Accounts/Finance.
2. **Users without an access row are unrestricted in the scoping helpers**
   (`_institutionally_scoped` in `views.py`). This is safe only because
   `/login/` refuses such users (pinned above) and `/admin/` needs `is_staff`.
   Hardening option: deny by default. It touches many tests, so it is a
   separate task.
