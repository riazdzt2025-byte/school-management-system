# সেশন-রিপোর্ট (docs/prompts/reports)

প্রতিটি প্রম্পট সেশন শেষে এজেন্ট এখানে একটি ছোট রিপোর্ট রাখবে: `reports/<সেশন-ID>.md` — যেমন `EX-01.md`, `DB-05.md`, `FN-01.md`।

রিপোর্টে যা থাকবে (প্রতিটি দাবির পাশে প্রমাণ):

1. **আগের অবস্থা → এখনকার অবস্থা** (কী বদলেছে, কী বদলায়নি)
2. **প্রমাণ:** চালানো কমান্ড + প্রকৃত ফল (টেস্ট সংখ্যা, `check`, `makemigrations --check`, CI check)
3. **পরিবর্তিত ফাইল** (সংক্ষিপ্ত তালিকা)
4. **যাচাই হয়নি এমন অংশ** (Unverified) — কেন সম্ভব হয়নি
5. **বাকি ঝুঁকি / পরবর্তী কাজ**
6. **owner-সিদ্ধান্ত** — প্রশ্ন · বিকল্প · সুপারিশ (থাকলে)

শেষে `docs/prompts/PROGRESS.md`-এর নিজের সারিতেও একই স্ট্যাটাস/commit/PR লিখতে হবে; রিপোর্ট সেটির বিস্তারিত সংস্করণ।

বিশেষ ফাইল:
- `০০-baseline.md` — প্রম্পট ০১ (সেশন ০০): ২৮ আইটেমের Complete/Partial/Missing/Unverified matrix।
- `EM-02-decision-request.md` — leave নীতির owner-সিদ্ধান্তের প্রশ্নপত্র (কোড লেখার আগে)।
- `FN-01.md` — চূড়ান্ত release verification: evidence table, risk register, go/no-go সুপারিশ।

⚠️ এখানে কোনো আসল ব্যক্তিগত ডেটা, credential, production DB-র সারাংশ বা কপি রাখা যাবে না — শুধু synthhetic/fixture-ভিত্তিক সংখ্যা ও কমান্ডের ফল।
