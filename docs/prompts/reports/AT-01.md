# AT-01 — Attendance entry / correction (prompt 23/28)

**Status: Complete (code + tests + docs).** Session date: 2026-11-03.

## আগের অবস্থা
- `mark_attendance` → `mark_attendance_bulk` entry flow, `update_or_create` per student/employee, institution scope, Office/Exam department gate.
- Audit only an aggregate `attendance_marked` row; no per-record correction page, no reason, no future-date guard in the bulk view.
- `attendance_report` was a plain date-descending log with no filters.

## এখন
- **Correction workflow** — `correct_attendance` (`/attendance/<pk>/correct/`): Office/Exam + `students.change_attendancerecord`, institution-scoped 404 for other schools, status/remarks editable, **mandatory reason**, old status/remarks + new values + reason written to `AuditLog` (`attendance_corrected`). The date and the student/employee are fixed.
- **Report filters** — start/end date, class, section, status, target (student/employee); every row shows a permission-gated **Correct** link.
- **Future dates blocked server-side** in `mark_attendance_bulk` (not just hidden in the UI); invalid status values are skipped with a warning instead of being written.
- **Permissions** — Office and Exam groups get `view/add/change_attendancerecord`; a user without the change permission gets 403 on the correction URL.
- **Rate definition** (shared with AT-02): `(Present + Late) / (Present + Absent + Late)`, `H` excluded, no-record never absent. `attendance_summary` and the employee detail now use the same helper.
