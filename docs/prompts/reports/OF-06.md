## এখনকার অবস্থা (✅ Complete — code + local proof; CI/merge owner-নির্ভর)

### (ক) Success page → printable slip

- `students/templates/students/public_admission_success.html` — নতুন slip: বড় monospace **application number** (`#application-number`), জমা দেওয়ার তারিখ/সময়, requested class/section/group ও session, institution, **masked** guardian contact (`*******5678` — পুরো নম্বর কখনো নয়), “What happens next” ৩ ধাপ (office review → payment → enrolment), “No payment is collected on this page”।
- **Print:** `@media print` block — hero/সাজসজ্জা সাদা-কালো, `.no-print` (button/nav) ছাপায় বাদ; `window.print()` “Print slip” button। রেন্ডার্ড HTML-এ pin করা টেস্ট।
- **Copy + WhatsApp:** `Copy details` button (`navigator.clipboard`, data-copy = share text) + `https://wa.me/?text=…` (`target="_blank" rel="noopener noreferrer"`)। share text = application number + institution + **public** status URL (`request.build_absolute_uri(reverse('public_admission_status'))`)।
- **Internal link সরানো:** পুরোনো `← Back to Home` (`{% url 'dashboard' %}`) সরিয়ে শুধু public route রাখা — `public_admission_apply`, `public_admission_status`। ভাড়া করা template-source pin + রেন্ডার্ড-HTML pin দুটোই আছে।

### (খ) নতুন public status/progress page

- Route: **`admission/status/`** → `views.public_admission_status` (name `public_admission_status`), template `students/public_admission_status.html`।
- দুটি field: `application_number` (lowercase / space / hyphen / `APP-` prefix ছাড়াও চলে — `normalize_application_number`) এবং `contact_last4` (বাংলা অঙ্কও চলে, `normalize_guardian_contact` পুনঃব্যবহৃত; ঠিক ৪ ডিজিট)।
- উত্তর: headline + masked name (`R*** U***`) + masked contact + class/section/session (+ ENROLLED-এ **Student ID**) + **4-ধাপের timeline** (done/current/todo, প্রতিটি ধাপের তারিখ) + “What happens next” applicant-facing text। মাত্র **একটি** SELECT (select_related সহ)।
- REJECTED: timeline “Application received → Review finished” (closed), headline “Application closed”, বার্তা = অফিসে যোগাযোগ; কারণ/remark কিছুই নয়।

### (গ) Privacy / safety

- **Generic error:** ভুল application number, ভুল contact tail, malformed input, missing field — সব ক্ষেত্রেই **একই** `PUBLIC_STATUS_NOT_FOUND_ERROR`; টেস্টে দুই response body byte-identical (শুধু visitor-এর নিজের typed number echo করা input value normalize করে; length-ও সমান)।
- **Masking:** নাম `R*** U***` (fixed-width), contact `*******5678`; full নাম/guardian নাম/amount/actor/remarks কখনো HTML-এ যায় না — view-wording fixed mapping (`PUBLIC_STATUS_MESSAGES`), মডেলের `next_step`/`office_remarks` template-এ নেই (template-source pin)।
- **noindex:** তিনটি public template-এই `<meta name="robots" content="noindex, nofollow">` (form/slip/status)।
- **Rate limit (reuse P1-9 helper, new scopes):** একই address থেকে ৩০ lookup / ১০ মিনিট (`rl:public_status:<ip>`) + একই (address, application number) pair-এ ৫টি ভুল / ১৫ মিনিট lock (`rl:public_status_fail:<ip>:<number>`)। সঠিক তথ্য দিলে ওই pair-এর counter মুছে যায়; ভিন্ন application/ভিন্ন address প্রভাবিত হয় না; `X-Forwarded-For`-এর বাঁ দিক spoof করে bypass করা যায় না (ডান-প্রান্তের IP-তেই key)। counter store `RATE_LIMIT_CACHE=db` হলে worker/restart জুড়েও কাজ করবে (কোনো নতুন dependency নেই)।
- **Cross-applicant isolation:** A-এর number + B-এর tail (বা উল্টো) → শুধু generic message; B-এর নাম/app number কখনো দেখা যায় না (দুই দিকেই pinned)।
- **Query string দিয়ে নয়:** শুধু POST-এ lookup; `?application_number=…&contact_last4=…` GET-এ কিছুই দেখায় না (pinned)।

### (ঘ) Notification

- কোনো email/SMS/payment activation নেই (owner approval নেই)। দুটি টেস্ট: public view-গুলোর source-এ `send_mail`/`EmailMessage`/`sms` নেই, এবং POST-এ `django.core.mail` mock করা থাকে (called নয়)।
