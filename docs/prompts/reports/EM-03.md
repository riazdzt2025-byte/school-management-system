# EM-03 — Payroll controls / closed-period lock (prompt 27/28)

**Status: Complete (code + tests + docs).** Session date: 2026-11-03.

## আগের অবস্থা
- `SalarySheet` had a unique `(employee, month)` constraint and money validation, but **no closed-period lock**: a PAID sheet could still be edited or deleted.

## এখন
- New `locked_at`, `locked_by`, `lock_reason` fields on `SalarySheet` (migration `0052`).
- **Lock** (`/accounts/salaries/<pk>/lock/`, POST, `change_salarysheet`): freezes amount/status/date; audited (`salary_sheet_locked`).
- **Unlock** (`/accounts/salaries/<pk>/unlock/`, POST): audited (`salary_sheet_unlocked`) with the previous lock snapshot.
- Edit and delete refuse a locked sheet with a clear message; the list shows **Locked/Open**, the lock date, and Lock/Unlock actions.
- Locking is separate from PAID: a paid sheet can still be corrected, and an unpaid sheet can be closed when the month ends.
- Institution-scoped: another school's sheet is 404.

## প্রমKeyDown
- New `students/test_payroll_lock.py`: lock + audit, edit blocked, delete blocked, unlock restores editing + audit, idempotent lock, cross-institution 404, list shows lock state/actions.
- Full suite: **1131 Django + 29 Node pass**, `check` 0, `makemigrations --check` clean.

## যাচাই হয়নি / ঝুকি
- Live Render, Postgres (CI only). No production DB touched.
- No bulk month-close action (per-sheet lock only); no payroll deduction policy (EM-02 remains blocked).

## Owner decision applied
- Lock is an audited, reversible action; Accounts owns it; a locked sheet is read-only.
