# AT-02 — Attendance calendar / report accuracy (prompt 24/28)

**Status: Complete (code + tests + docs).** Session date: 2026-11-03.

## আগের অবস্থা
- `attendance_report` (log) and `attendance_summary` (date range + rates) existed; **no calendar view**, no central holiday model (H is a per-record status).
- Rate was `present / total` including holidays; archived students could appear in the summary.

## এখন
- **Monthly calendar** (`/attendance/calendar/`, server-rendered, no new JS dependency): Sunday-first grid, colour-coded P/A/L/H badges, per-day rate, "No record" for days without records, Today marker, previous/next month with year rollover, invalid year/month fall back safely.
- Filters: class, section, target (students/employees), institution (session/selection scoped).
- Day cell → correction page when exactly one record exists and the user holds the permission; otherwise the filtered report.
- **Monthly summary** table (one row per student/employee) + **CSV export** (`/attendance/calendar/export/`).
- **Accuracy:** rate = `(P + L) / (P + A + L)`, H excluded; archived students excluded from calendar, summary and export; employee and student modes use the same source; summary page and employee detail now use the same helper. Formula printed on the page and in the docs.
- Print CSS; no new JS library.

## প্রমাণ
- New tests in `students/test_attendance_correction_calendar.py`: grid/legend, 75% rate with H excluded, archived excluded, other institution excluded for a scoped clerk, invalid month fallback, month rollover, employee mode, CSV contents/rate, correction link.
- Full suite: **1131 Django + 29 Node pass**, `check` 0, `makemigrations --check` clean.

## যাচাই হয়নি / ঝুকি
- Live Render, actual print/PDF, Postgres (CI only). No production DB touched.
- A central institution-level holiday calendar is still not modelled; H remains a per-record status (documented, smallest coherent change).

## Owner decision applied
- H excluded from the denominator; L counted as attended; no record is not absent.
