# EM-01 — Employee / teacher assignment (prompt 25/28)

**Status: Complete (code + tests + docs).** Session date: 2026-11-03.

## আগের অবস্থা
- Employee CRUD, status change + history + audit, institution scoping and salary sheets existed.
- **No teacher ↔ class/section/subject assignment model** — the class teacher/subject teacher registry was missing.

## এখন
- New `TeacherAssignment` model (migration `0052`): institution, employee, class, section (blank = all sections), subject, session, `is_active`, created_by, timestamps.
  - **Validation:** class must be offered by the institution; employee must belong to the institution; subject must be in the class curriculum when `SubjectRequirement` rows exist; session required.
  - **Uniqueness:** one *active* row per institution+employee+class+section+subject+session (conditional unique constraint); friendly form error + race-safe `IntegrityError` fallback.
- UI: registry list with filters (class/section/subject/session/status), add/edit, **Unassign** (soft `is_active=False`, history kept) and hard delete (audited). Employee detail has an **Assignments** tab.
- Permissions: HR and Office get full assignment rights; Exam gets read-only (signature sheet). Server-side gates on every view; institution-scoped 404 for other schools.
- Integration: the exam **signature sheet** prints the active subject teachers for the exam's class/section/session.
- Audit: created / updated / toggled / deleted rows.

## প্রমাণ
- New `students/test_teacher_assignment.py`: valid create + audit, duplicate blocked, class not offered rejected, subject outside curriculum rejected, employee from another institution rejected, list renders, 403 without permission, cross-institution edit/toggle 404, signature sheet shows the teacher, unassign removes it, employee detail tab.
- Full suite: **1131 Django + 29 Node pass**, `check` 0, `makemigrations --check` clean.

## যাচাই হয়নি / ঝুকি
- Live Render, Postgres (CI only), real browser. No production DB touched.
- Assignment granularity is class+section+subject (owner recommendation); a separate "class teacher" field is not added.
- `class_section_summary` integration was not added (only the signature sheet + employee detail); can be a follow-up.

## Owner decision applied
- HR + Office may assign; session-wise history retained via `is_active`; one active assignment per teacher/class/section/subject/session.
